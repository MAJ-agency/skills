## Règles à tenir

Elles viennent du produit et de la chaîne ; les reprendre telles quelles dans tout prompt de session lancée :

- Le produit : « arrête de me demander des autorisations fais tout ce qu'il faut pour avancer » et « Les seules questions auxquelles je dois répondre sont des décisions techniques ou métier pas des autorisations que je ne fais qu'accepter de toute façon. »
- Intangibles : jamais --no-verify ; jamais de push forcé ni de réécriture d'historique ; jamais de fusion avec un contrôle exigé rouge ; jamais de test sauté ou assoupli ; jamais de push sur la branche par défaut ; une dépendance nouvelle attend l'accord humain.
- Commits : jamais `git commit --amend` ; une correction est un commit de plus.
- L'architecte ne fusionne jamais : il contre-relit, pose l'ordre `à-fusionner au sommet <sha40>` puis le label, et c'est le capitaine (ou le produit) qui fusionne. Une seule PR étiquetée à la fois (A-48). Une PR qui touche du code passe une contre-relecture adversariale avant l'ordre. Le programme a appris ceci :
  - attendre CodeQL vert : deux alertes `js/incomplete-sanitization` sur des `replace` par motif à plusieurs caractères ont renvoyé des PR ;
  - classer la sortie d'un script sur sa dernière ligne, jamais sur un motif cherché dans une sortie qui relaie un hook ;
  - toute lecture GitHub qui décide d'un état passe par `lire_github`, et un refus donne 5 ;
  - toute sortie de git relayée passe par `git_masque` ou `masquer_url`.
- La langue : prose en français, identifiants en anglais (conventions du dépôt `MAJ-agency/skills`, `CLAUDE.md`, `docs/agents/`).
