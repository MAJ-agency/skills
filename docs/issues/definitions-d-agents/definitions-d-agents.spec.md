# Définitions d'agents — spec

Programme : [`../../programmes/definitions-d-agents.programme.md`](../../programmes/definitions-d-agents.programme.md). État : **`P-1` tranchée le 2026-11-27 : oui** (« avoir un contexte vierge et ne pas aller voir tout le projet ») ; tickets 1 et 2 prêts.

## Le problème

Les skills de travail de la chaîne lancent leurs sous-agents de revue par l'outil Agent, avec un agent générique et un prompt fabriqué à la volée. La lecture seule et le contexte vierge ne tiennent que par le texte du prompt (« tu ne modifies rien, tu ne lances aucune commande qui écrit »), et le modèle est celui de la session qui lance. Le produit veut des sous-agents **définis** : des fichiers de définition livrés par le plugin `maj-skills` (dossier `agents/` d'un plugin Claude Code), qui fixent le rôle, les outils et le modèle ; les skills les lancent par leur nom et continuent de fabriquer le message de la tâche par leurs scripts.

## Faits établis (documentation et essais du 2026-11-25)

Sources : la page des sous-agents (`https://code.claude.com/docs/en/sub-agents`) et la référence des plugins (`https://code.claude.com/docs/en/plugins-reference`) ; six essais réels dans une session cloud, Claude Code 2.1.332, par `claude -p --plugin-dir <plugin de sonde>` lancé depuis la session, les transcripts des sous-agents lus sur le disque (`~/.claude/projects/<projet>/<session>/subagents/agent-*.{jsonl,meta.json,prefix.json}` : `toolNames`, `model`, pièces jointes de contexte). Sonde : un plugin `sonde` à deux agents, `tools: Read, Grep, Glob`, `model: haiku`, l'un avec `omitClaudeMd: true` et `skills: [sonde:canari]`, l'autre sans ; un projet balisé (chaînes « CANARI- » dans `CLAUDE.md`, `.claude/rules/`, un CLAUDE.md de sous-dossier, le prompt du parent, le skill).

1. **Les outils.** La liste `tools:` est la seule liste : `toolNames` vaut `["Read","Grep","Glob"]` ; Write, Bash et Agent n'existent pas pour l'agent (il ne peut ni écrire, ni lancer une commande, ni lancer un sous-agent), et l'autorisation du parent (`--allowedTools Write Bash Agent`) n'y change rien. `tools: []` ou `tools: ""` donne `toolNames: []`, et l'agent se lance. Doc : « Inherits every tool available to subagents if omitted » ; `disallowedTools` retire un outil entier.
2. **Le modèle.** Le `model:` du fichier s'impose : lancé depuis une session Sonnet, l'agent tourne sur `claude-haiku-5-5` ; avec le paramètre `model: "opus"` de l'outil Agent, `meta.json` note `"model":"opus"` mais les requêtes partent encore sur `claude-haiku-5-5` (`prefix.json` et chaque message). Valeurs : `sonnet`, `opus`, `haiku`, `fable`, un identifiant complet, ou `inherit`. L'effort n'est fixé que par le champ `effort:` ; absent, il suit la session.
3. **Le nom.** Un agent du dossier `agents/` du plugin `maj-skills` s'appelle `maj-skills:<nom>` (doc : « an agent `reviewer` in plugin `deploy-tools` appears as `deploy-tools:reviewer` » ; essai : `sonde:vierge` dans la liste des agents de la session). Un nom ne contient pas `:`. Un nom inconnu est une erreur franche de l'outil, sans repli : « Agent type 'maj-skills:inexistant' not found. Available agents: … ». Priorité, de la plus haute à la plus basse : réglages gérés, `--agents`, `.claude/agents/` du projet, `~/.claude/agents/`, plugin : un projet peut masquer un agent du plugin sous le même nom… mais pas sous `maj-skills:<nom>`, réservé au plugin. `hooks`, `mcpServers` et `permissionMode` sont ignorés pour un agent de plugin.
4. **Précharger un skill** : `skills: [<plugin>:<skill>]` injecte le texte entier du skill au démarrage (essai : la chaîne du skill dans le premier message de l'agent).
5. **Ce que l'agent reçoit d'office.** Son corps comme prompt système (pas celui de Claude Code), l'environnement (dossier de travail, plateforme), la date, le modèle ; ni l'historique de la session (la chaîne du prompt parent n'apparaît dans aucun agent), ni la liste des skills quand il n'a pas l'outil Skill. **Par défaut, le `CLAUDE.md` du projet et les fiches `.claude/rules/`** (pièce jointe `instructions`) : c'est vrai d'un agent défini sans réglage **et de l'agent générique `general-purpose` d'aujourd'hui** (essai : les deux citent le `CLAUDE.md` de `skills` et la règle de sonde). **Avec `omitClaudeMd: true`, ni l'un ni l'autre** (doc : « start this subagent without the user, project, and local CLAUDE.md files in its initial context; managed policy files still load »). Mais un `CLAUDE.md` de sous-dossier arrive encore, avec ou sans le réglage, dès que l'agent lit un fichier de ce dossier (essai : la chaîne d'un `sous/CLAUDE.md` dans le contexte des deux agents après un `Read` de `sous/a.txt`).
6. **Une session partie d'un instantané plus ancien.** Les agents se chargent au démarrage de la session : un fichier ajouté en cours de session (`~/.claude/agents/sonde-chaude.md`) reste « not found », et `claude plugin update`, qui ne recharge pas les skills (`architecte/references/lancement.md`, « La mise à niveau »), ne recharge pas davantage les agents. Une session cloud partie d'un instantané où le plugin est antérieur à cette version n'a donc pas les définitions, pour toute sa durée : chaque skill qui les nomme a besoin d'un repli.

**Ce que le fait 5 change.** Les axes « en contexte vierge » de `relecture`, `revue-de-ticket` et `revue-adversariale`, et le classeur de `criticite` (« ne connaît que l'énoncé de la règle, sa spec et les définitions », mots du produit), reçoivent déjà aujourd'hui le `CLAUDE.md` et les fiches de la session qui les lance, à côté de leur message. Pour `relecture`, c'est le `CLAUDE.md` du dossier de la session (la base de la PR, puisque la session part de la base), que l'empreinte de `gestes.sh` suit déjà (`consignes_autour`) ; les prompts des axes disent en plus de lire `CLAUDE.md` et `.claude/rules/` dans `{{BASE}}`. Pour `criticite`, c'est un écart à la décision du produit.

## Ce qui change, vu par le produit

- Les relectures (axes de `relecture`, de `revue-de-ticket`, relecteur de `revue-adversariale`, relecture d'un ticket hors chantier par l'architecte, contre-revue du régime 7) partent d'un agent qui **ne peut que lire** (aucun outil d'écriture ni de commande), sur **Opus**, **sans les consignes du projet dans son contexte** (`P-1`) : il lit lui-même les règles là où son message le lui dit.
- Le classeur de `criticite` part d'un agent **sans aucun outil**, sur Opus, sans les consignes du projet : il ne voit plus que le message fabriqué par `contexte-regle.mjs`.
- Une session qui n'a pas encore les définitions (instantané ancien) relit comme aujourd'hui, et **le dit** dans sa sortie.
- Rien à reposer dans un projet : les définitions et les skills qui les nomment sont lus dans le plugin.

## Décisions de conception (architecte)

- **A-1 — Deux définitions**, dans `agents/` à la racine du plugin (la racine du dépôt, `source: "./"`), déclarées par une liste `agents` dans `.claude-plugin/plugin.json`, comme les skills (la liste remplace le balayage par défaut : une définition non listée n'est pas livrée, et le banc le voit). Raison : le dépôt déclare déjà chaque skill ; une liste se teste.
  - `maj-skills:axe-de-relecture` — `tools: Read, Grep, Glob` ; `model: opus` ; `omitClaudeMd: true` ; ni `effort`, ni `skills`, ni `maxTurns`. Pour : chaque axe de `relecture` (les cinq prompts), les trois axes de `revue-de-ticket`, le relecteur de `revue-adversariale` (et ses lots), la relecture d'un ticket hors chantier par l'architecte (`architecte/SKILL.md` § 5), la contre-revue du conducteur et de l'architecte en régime 7 (`chantier/references/regime-7.md`).
  - `maj-skills:classeur-de-criticite` — `tools: []` ; `model: opus` ; `omitClaudeMd: true`. Pour : le sous-agent de `criticite` (étape 3), et son second essai hors format.
- **A-2 — Lecture seule par Read, Grep, Glob, sans Bash.** Raison : aucun prompt de revue ne demande une commande (le diff, la résolution `--remerge-diff`, le contexte du ticket, la section `## Criticité` sont fabriqués par les scripts ou la session et passés dans le message ou sur le disque) ; Bash rendrait l'écriture possible, ce que la définition doit rendre impossible. Un prompt qui demanderait plus est un écart, à corriger dans le prompt.
- **A-3 — Opus, effort non fixé.** Raison : c'est le modèle des sessions de relecture (`relecture.ordinaire` et `relecture.sensible` du contrat, `opus`) ; l'effort reste celui de la session, pour qu'une PR sensible garde `xhigh`. Surcoût : les axes de `revue-de-ticket` d'une fille Sonnet passent sur Opus. Le modèle du fichier s'impose à l'appelant (fait 2) : un skill ne passe plus de paramètre `model`.
- **A-4 — Le corps de chaque définition est court et générique** : le rôle (un relecteur en contexte vierge, ou un classeur), « ta mission, ta liste fermée et ton format de sortie sont dans ton message ; tu ne rends que ce qu'il demande ». Il ne recopie aucun critère, aucun format : les prompts des skills restent la source, fabriqués comme aujourd'hui. Sa `description` dit qu'il ne se lance que par un skill de `maj-skills` qui le nomme, jamais de lui-même : une session pourrait sinon lui déléguer une autre tâche sur sa seule description.
- **A-5 — Aucun skill préchargé.** Raison : tout ce qu'il faut à l'agent est dans son message ; un skill préchargé entrerait dans un contexte qui doit rester vierge.
- **A-6 — Le repli.** Chaque skill lance l'agent par son nom (`subagent_type: "maj-skills:<nom>"`) ; si l'outil répond « Agent type '…' not found » (instantané antérieur à cette version, fait 6), la session relance **le même message, entier**, par l'agent générique d'aujourd'hui, et le dit en une ligne dans sa sortie : la section de PR (`revue-de-ticket`, `revue-adversariale`, `criticite`), le verdict (`relecture`), la conclusion lue par l'architecte. Le repli n'est pas une panne : l'axe est joué. Toute autre erreur de l'outil garde la règle de chaque skill (« non exécuté », second essai…). Raison : arrêter la chaîne jusqu'au renouvellement de l'instantané (jusqu'à sept jours) coûterait plus que relire comme aujourd'hui ; le dire permet de compter les replis.
- **A-7 — La garde des consignes de `relecture` reste** (`gestes.sh`, `SANS_CONSIGNES`, `consignes_autour`) : `omitClaudeMd` n'empêche pas un `CLAUDE.md` de sous-dossier d'arriver à la lecture (fait 5).
- **A-8 — Les skills de rôle ne changent pas**, hors `architecte` § 5 (point de la relecture d'un ticket hors chantier), `chantier/references/regime-7.md` (contre-revue) et le paragraphe d'`architecte/references/lancement.md` qui décrit la contre-relecture de l'architecte par un sous-agent (régime 7 et dépôt sans la chaîne), vers lequel `regime-7.md` renvoie : c'est le même geste, écrit à deux endroits. Les sous-agents de relevé ou de rédaction (`Explore` de `recette-humaine`, rédaction de tickets, `Explore` d'une fille) gardent tous leurs outils : hors périmètre.
- **A-11 — Sans `CLAUDE.md` d'office, le prompt fait lire les règles.** Chaque prompt d'un axe ou d'un relecteur qui juge contre les règles du projet dit de lire d'abord, avant de juger, le `CLAUDE.md` de la racine et ceux des dossiers que le diff touche, et les fiches `.claude/rules/` (dans `{{BASE}}` pour `relecture`, dans le dépôt pour `revue-de-ticket` et `revue-adversariale`), au lieu de « tu peux lire … pour vérifier un point ». Raison : avec `omitClaudeMd`, ces règles n'arrivent plus d'elles-mêmes ; sans cette phrase, un critère qui renvoie aux règles du projet dépendrait d'une lecture facultative. Le prompt du classeur de `criticite` ne change pas : il ne doit rien lire.
- **A-12 — Le glossaire.** « Agent défini » entre à `CONTEXT.md` (ticket 1) : une définition du plugin, lancée par un skill par son nom `maj-skills:<nom>`, qui fixe outils, modèle et contexte.
- **A-9 — Un banc** (`scripts/agents.test.mjs`, joué par `pnpm test`) tient : chaque fichier de `agents/` est listé dans `plugin.json` et inversement ; chaque définition a `name` (égal au nom du fichier), `description`, `tools` exactement comme A-1, `model: opus`, `omitClaudeMd: true`, ni `hooks`, ni `mcpServers`, ni `permissionMode` ; chaque `maj-skills:<nom>` cité sous `skills/` désigne une définition existante ; les skills de A-1 nomment leur agent et portent la phrase du repli.
- **A-10 — Deux tickets, une version mineure chacun** (`8.4.0`, puis `8.5.0`), le second bloqué par le premier : fichiers chauds communs (`plugin.json`, `marketplace.json` si sa description change, `NOTES-DE-VERSION.md`, `README.md`). Pas de conducteur ni de sujet : chaque ticket est une session hors chantier lancée par l'architecte, comme sur ce dépôt depuis `A-17` du programme « capitaine à jour et testé ».

## Hors périmètre

- Les sous-agents de relevé ou de rédaction (A-8).
- Les sessions de relecture elles-mêmes (`create_session` du Relecteur) : ce ne sont pas des sous-agents.
- Un agent défini pour un rôle de session (conducteur, capitaine) : les rôles restent des skills lus dans leur fichier.
