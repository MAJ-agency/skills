# CLAUDE.md

Machine-readable rules for generating code in this NestJS backend. These are **imperative constraints**, not explanations. The _why_ lives in [docs/ARCHITECTURE_GUIDELINES.md](docs/ARCHITECTURE_GUIDELINES.md) and in the project ADRs ([`../../docs/adr/`](../../docs/adr/)) — read them when a rule is unclear, but the rules below are binding and win on conflict.

Architecture: **hexagonal (ports & adapters)**. Work **domain-first**: define the domain and its ports before writing any adapter.

Stack (non-negotiable): **Kysely** (not TypeORM/Prisma) · **Zod / `nestjs-zod`** for validation (not `class-validator`) · **Vitest** · **pnpm** · Node ≥ 22. Domain vocabulary is **French** — keep it.

> **Provenance.** Generated by the `socle-nest-hexagonal` skill. It carries **configuration rules only** — no business rule ever belongs here. Kept in English so it stays diffable against the upstream template when it evolves; the rest of the repo's documentation is in {{LANGUE}}.

> **State note.** The skeleton exists and boots: path aliases, the `domain/application/infrastructure` tree, the `check`/`check:arch`/`check:cycles` scripts, global validation pipe and error filter, OpenAPI generation. **No domain is modelled** — `application/` is empty, there is no database layer yet. `src/db/`, migrations and `kysely-codegen` arrive with the first entity; don't assume they're there.

> **Still open.** Decisions the scaffold deliberately did NOT make are filed as tickets under `docs/features/socle/issues/`, each with its options and its consequence. Settle one, then record it as an ADR — never adopt or drop one silently.

## Golden rule — dependency direction

Dependencies point **inward only**: `infrastructure → application → domain`.

- **MUST**: `domain/` imports nothing from `application/` or `infrastructure/`.
- **MUST**: `application/` imports only from `domain/` (and its own layer). Never from `infrastructure/`.
- **MUST**: concrete adapter classes are referenced **only** inside a module (the composition root). No other file imports a concrete adapter — only its port interface.
- **VERIFY**: `domain/` + `application/` must compile with `infrastructure/` deleted. Run `pnpm --filter @{{SCOPE}}/{{PROJET}}-api check:arch` (see [Verification](#verification)).

## Living reference

The socle ships no business feature. **The first real feature (domain + use case + adapter + tests) becomes the living reference**: before creating another one, read it entirely and reproduce its shape. When it drifts from this file, fix one of the two — never let them disagree in silence.

## Imports — path aliases (MANDATORY)

Use TypeScript path aliases. **NEVER** use deep relative imports (`../../../...`).

- `@domain/*` → `src/domain/*`
- `@application/*` → `src/application/*`
- `@infrastructure/*` → `src/infrastructure/*`
- `@shared/*` → `src/domain/shared/*`
- `@test/*` → `src/utils/tests/*`
- `@db/*` → `src/db/*` (DB artefacts outside the hexagon: generated `types.ts` — repositories import it through this alias)

- **MUST**: import via alias, e.g. `import { Titre } from '@domain/titre/models/titre/titre'`.
- **NEVER**: `import { Titre } from '../../../../domain/titre/models/titre/titre'`.
- Same-folder / sibling imports (`./x`, `../dto/x`) are allowed. The ban is on crossing layers with relative paths.

> Required config (create if absent). `tsconfig.json`:
>
> ```jsonc
> "compilerOptions": {
>   "baseUrl": "./",
>   "paths": {
>     "@domain/*": ["src/domain/*"],
>     "@application/*": ["src/application/*"],
>     "@infrastructure/*": ["src/infrastructure/*"],
>     "@shared/*": ["src/domain/shared/*"],
>     "@test/*": ["src/utils/tests/*"],
>     "@db/*": ["src/db/*"]
>   }
> }
> ```
>
> Vitest must mirror these via `resolve.alias` (or `vite-tsconfig-paths`).

## Frozen architecture decisions

These are **project decisions**, not open questions. Do not deviate.

- **DECISION — Kysely, never an ORM.** No TypeORM, no Prisma, no `@Entity` decorators, no `@InjectRepository`. Data-row types are generated from the live schema by `kysely-codegen` into `src/db/types.ts` and are **never written by hand** — not even one field. Workflow: write the migration → `migrate` → `db:types`. CI regenerates and diffs (`db:types:check`): any drift or manual edit fails the build. When a generated row type collides with a domain model name, alias it at the import site (`import type { Account as AccountRow } from ".../db/types"`).
- **DECISION — Zod is the only validation grammar.** Input DTOs derive from the contracts schemas via `createZodDto` (`nestjs-zod`) and are validated by the global `ZodValidationPipe`. **NEVER** introduce `class-validator` or `@ApiProperty` — it would be a second grammar and reopen the decision.
- **DECISION — no use-case-to-use-case calls.** A use case **NEVER** calls another use case. Shared logic spanning entities goes into a **domain service** (`@domain/<domain>/services/`), injected by token into both use cases.
- **DECISION — inter-module communication via exposed port only.** When module A needs domain B, A depends on a **port B exposes** (an API use-case port or a dedicated SPI), wired by token in A's module. **NEVER** import B's repository, row type, or internal model directly across modules. For async decoupling, publish/subscribe **domain events** instead.
- **DECISION — UUID v7, generated in the application.** Identifiers are minted app-side, not by the database.

- **DECISION — single-tenant (`ARC-2`).** There is no `tenant_id`, no Row-Level Security, no `runInTenant`. **NEVER** introduce a tenant column or an RLS policy — that would reopen `ARC-2`, which was decided on purpose.

- **DECISION — multi-tenant, isolation by Row-Level Security (`ARC-2`).** Every tenant table carries `tenant_id NOT NULL`, with `ENABLE` **and** `FORCE ROW LEVEL SECURITY`, and a policy carrying `USING` **and** `WITH CHECK`, fail-closed on a session setting. The runtime connects with a **`NOBYPASSRLS`** role; migrations and seed run as the **owner** role — **NEVER** an application query with the owner role. A table without tenant scope is an **ADR** naming the table, why, and what replaces RLS as proof of ownership; those tables are the versioned allowlist of the isolation gate.
<!-- ══ /TENANT-B ══ -->
<!-- ══ ROLES-A ══ -->
- **DECISION — no role catalogue (`ARC-2`).** Authorisation is ownership, proven in the use case. **NEVER** introduce a role or permission table — that would reopen `ARC-2`.
<!-- ══ /ROLES-A ══ -->
<!-- ══ ROLES-B ══ -->
- **DECISION — roles: closed catalogue in code, assignment in data (`ARC-2`).** The role catalogue is a **closed tuple in `packages/contracts/src/roles.ts`** (`as const` + `z.enum`; code, typed, reviewed). Who holds which role is **data**, in a table like any other. What a role permits is a rule **written in the use case** — **NEVER** a `permission` table. The role travels with the **authenticated session**, **NEVER** in a header or a body; a client may hide an action by role, the API alone decides.
<!-- ══ /ROLES-B ══ -->
- **DECISION — no client, for now.** The {{TITRE}} ships **no user interface**: it is a headless API, and its published surface is the OpenAPI document. Zod schemas live in `packages/contracts` (`@{{SCOPE}}/{{PROJET}}-contracts`). **Do not build browser-shaped machinery** — no session cookie flow, no CSRF, no CORS credentials design — until a client exists and its nature is known (browser? mobile? Apple/Google projet pass?). Each answer wants a different auth shape.

## Transactions

<!-- ══ TENANT-A ══ -->
A use case that writes more than one row wraps its work in the `IUnitOfWork` port. It is a **transaction boundary and nothing else** — a tenant-scoped `runInTenant` is deliberately absent (`ARC-2`).

- **MUST**: multi-write work goes through `IUnitOfWork.run(work)`. Either everything commits, or nothing does.
- **Ownership is proven in the use case**, explicitly, inside the transaction: a resource belongs to the authenticated account or the request is refused. With no RLS there is **no backstop** — the explicit check _is_ the protection, so it is never optional and never inferred from a foreign key.
<!-- ══ /TENANT-A ══ -->
<!-- ══ TENANT-B ══ -->
Every access to tenant data goes through the `IUnitOfWork` port: **`runInTenant(tenantId, work)` is the only path to a tenant row** (`ARC-2`). It is a transaction boundary **and** the tenant scope.

- **MUST**: all tenant-scoped work — reads included — goes through `IUnitOfWork.runInTenant(tenantId, work)`. Either everything commits, or nothing does. Its adapter opens a transaction and sets the tenant setting **`LOCAL`** (cleared at COMMIT, immune to pool connection reuse). **NEVER** a non-`LOCAL` `SET` nor `set_config(..., false)`: it would leak between requests on a pooled connection.
- **MUST**: the `tenantId` **never** comes from a client header or body. Either it is a URL coordinate **proven under RLS** — inside the transaction, a `SELECT` on the target resource must find it, else 404 — or it comes from the authenticated session. That proof `SELECT` is **mandatory**: foreign-key constraints bypass RLS, so without it a row of tenant B can reference a resource of tenant A.
- **RLS is a backstop, not a licence**: repositories still target the right rows explicitly, and ownership **inside** a tenant (a resource belongs to the authenticated account) is still proven in the use case. RLS guarantees that a bug does not become a cross-tenant leak.
<!-- ══ /TENANT-B ══ -->
- **MUST**: the transaction travels **ambiently** (continuation-local store, `nestjs-cls`), never as a `trx` parameter on a port method. A port signature must stay expressible without naming the database.
- **MUST**: Kysely (`db`, `Transaction`, `sql`) is imported **only** in infrastructure — never in `domain/` or `application/`. Enforced by lint and by `check:arch`.

## Layer rules

### Domain (`src/domain/`)

- **MUST** be pure: no `@nestjs/*`, no Kysely, no `nestjs-zod`, no I/O.
- **MUST** enforce invariants at construction (constructor or static factory that throws a domain error). No anemic models.
- **Value objects**: immutable, equality-by-value, self-validating (`Montant` in cents, `Email`, …). Prefer them over primitives for domain concepts.
- **Domain services**: stateless, for multi-entity logic that belongs to no single entity.
- **Domain errors**: extend `DomainError` (abstract, carries a `code`). **NEVER** reference HTTP status codes in the domain — mapping happens in an exception filter.
- **Ports live here.** API ports in `api/<feature>/`, SPI ports in `spi/`.

### Application (`src/application/`)

- **Use case vs. service.** A **use case** answers a **business request**. A **service** is an internal _tool_ used by business logic or infra (domain service = pure; application service = orchestrates SPI ports; SPI adapter = touches tech). Discriminator: _does it answer a business request?_ — not _is it shared?_.
- **NEVER** create a use case that only forwards to one SPI port with no business logic. The tool already exists — expose it directly. A pure infra/security tool (e.g. CSRF token issuance) is called by the controller straight from its **SPI service** (`ICsrfService`), like a guard does — there is no `IssueCsrfUseCase`.
- A use case implements exactly **one** API port and exposes a single `execute()`.
- **NEVER** put `@Injectable()` on a use case — it is registered manually by token in the module.
- **MUST** inject dependencies as **port interfaces** by string token (`@Inject('ITitreRepository')`), never concrete classes.
- **MUST** throw domain errors; never throw `HttpException` from a use case.
- **NEVER** instantiate or depend on a concrete `@nestjs/*` **service** in a use case or application service. The layer may import `@nestjs/common` for its **DI decorators only** (`@Inject`, `@Injectable`) — the « no `@nestjs/*` » purity rule is `domain/`-only, but application services stay ports-first all the same. Every framework capability goes through an SPI port injected by token: **logging → `@Inject('IAppLoggerService')`, never `new Logger()`** ; config → typed config port (below) ; events → `IEventPublisher` ; outbound HTTP → a gateway port. **Enforce by lint** (`no-restricted-imports` on `src/{domain,application}`): an `import { Logger } from "@nestjs/common"` in the application layer **fails lint**.
- **NEVER** inject NestJS `ConfigService` into a use case. Depend on a typed config **port** instead. The environment is validated at boot (Zod, fail-fast) in **`src/config/env-configuration.ts`** ; only infrastructure imports `env`. Three families: (1) variables **independent of the env** → `.default()` in `env-configuration.ts` ; (2) variables **env-dependent, non-secret** → dev/test values in **`src/config/env.development.ts`** (committed, applied outside prod) ; (3) **local secrets** → **`.env`** (loaded by `dotenv`, **gitignored**), template in `.env.example`. In **production** no dev value is injected: a missing variable (or a secret < 32 chars, or a non-https `CORS_ORIGIN`) **fails the boot**.
- **Transactions**: use the `IUnitOfWork` port (`run`). **NEVER** import Kysely (`db`, `Transaction`, `sql`) into the application layer.

### Application services (shared collaborators)

- A collaborator shared by several use cases that **orchestrates SPI ports** (I/O) is **NOT** a domain service (those are pure) and **NOT** a use case (no inbound port).
- **MUST** live in `application/<domain>/services/` and be named `<name>.service.ts`.
- **MUST** depend only on SPI ports; never import concrete infrastructure.

### Mappers

- **MUST** be pure and synchronous: no I/O, no `async`, no URL signing.
- Trivial, dependency-free mapping → a **pure exported function** (`accountVersPublic(account): AccountPublicDto`). No class, no token, no wiring.
- Needs an injected dependency → an **injectable mapper behind a REAL interface** (`IXxxMapper` in `application/<domain>/ports/`, impl `@Injectable` in `mappers/`), wired by token.
- **NEVER a lying token**: a DI token named `"IXxxMapper"` **must** have a matching `IXxxMapper` interface that the injected field is typed by. An injectable + `"IXxx"` token without the interface is forbidden — use the pure function instead. (Applies to every port token, not just mappers.)

### Infrastructure (`src/infrastructure/`)

- **Inbound adapters** (controller / consumer / scheduler / CLI command) contain **NO business logic**. They (1) translate transport input into a port param object, (2) call `execute()`, (3) translate result/error back to transport.
- **Outbound adapters** implement an SPI port, map to/from **domain models** (never leak row types / external DTOs outward), log and rethrow on error.
- **Repositories (Kysely)**: read the ambient `Transaction<DB>` (via the unit-of-work adapter), keep row↔model mapping **private** to the repository. `Selectable<…>`/`Insertable<…>`/`Updateable<…>` types **never** cross the repository boundary. Atomic writes use `sql` tagged templates inside the repository.
- **External HTTP adapters** implement a port declared in the domain. External DTO shapes stay confined to the adapter and are mapped to domain types at its edge. Mock ↔ real is a one-line swap by token.
- **Input DTOs** derive from the contracts schemas via `createZodDto(SomeSchema)` in `infrastructure/<domain>/<feature>/dto/`, validated by the global `ZodValidationPipe`. Swagger is generated from the Zod schema (`nestjs-zod`), not from `@ApiProperty`.

## Invariants — recipes that MUST be respected

- **Concurrency on a limited resource.** Never read-then-write a counter that has a ceiling. Claim with a **single conditional atomic UPDATE** inside the repository: `UPDATE t SET pris = pris + 1 WHERE id = :id AND pris + 1 <= capacite RETURNING id`. `rowCount = 0` → the resource is exhausted → apply the domain's fallback. Pair it with an **idempotency key** (unique constraint on the row) so a replay never double-counts.
- **Idempotency.** Any mutation reachable twice (a retry, a webhook redelivery, a double click) carries a client-supplied idempotency key with a unique constraint. The use case looks it up **first**, inside the transaction, and returns the existing result on replay.
- **Auth — recipe on hold, browser-shaped.** With no client (above), none of this is implemented yet, and it is only correct for a **browser** client on a sibling subdomain. A mobile client wants bearer tokens; a {{TITRE}} pass wants signed passes and none of it. **Re-decide the shape when the client is known**, then apply: Argon2id (`@node-rs/argon2`), short access JWT in a `__Host-` httpOnly cookie, opaque refresh hashed at rest with **rotation + reuse detection** (reuse ⇒ revoke the whole family), CSRF **signed double-submit** (HMAC of the session id, `X-CSRF-Token` header). Both guards are **global** (`APP_GUARD`): every route requires auth by default and every authenticated mutation requires Origin + CSRF; safe methods (`GET`/`HEAD`/`OPTIONS`) skip CSRF. Opt-out is explicit via `@Public()` — reserve it for truly anonymous routes (login, refresh, health) and treat any new `@Public()` as a review point. Execution order is **`AuthGuard` then `CsrfGuard`** (CsrfGuard reads `req.session.sid`). Hardening: **JWT signed/verified with allowlist `algorithms: ["HS256"]`** (anti algorithm-confusion) ; **`CsrfGuard` requires `Origin` == `CORS_ORIGIN`** and rejects its **absence** on a mutation. Reuse detection **logs to `audit_log`**.
- **Audit trail.** A **sensitive business event** (a state transition that carries money, identity or entitlement) is business traceability: it belongs in the immutable append-only `audit_log` via the `IAuditLog` port, **not** in a `logger.error`. A technical log is ephemeral diagnostics; an audit entry is evidence.

## Contract boundaries — sealed type universes

- **Internal API** = Zod schemas (via `nestjs-zod`): they validate at runtime, type, and document. A client imports **only** the contracts — never a DB row type, never an external DTO.
- **Data** = `kysely-codegen` types in `src/db/types.ts`. They **never leave the repository layer**.
- **External APIs** = OpenAPI DTOs **confined to adapters**; mapped to internal types at the adapter edge. An external DTO never reaches the domain.

Enforce by lint (`no-restricted-imports` / `eslint-plugin-boundaries`) and replay in CI. Do not cross them.

## Ports naming

- API port: `I{Action}{Entity}UseCase` + `I{Action}{Entity}UseCaseParams`. Returns an **output DTO**, never a domain model.
- SPI port: `I{Entity}Repository`, `I{Vendor}Gateway`/`…Port`, `IAppLoggerService`, `INotifier`, `IEventPublisher`, `IAuditLog`, `IClock`, `ICache`, `IObjectStorage`, `IUnitOfWork`, `I{Domain}Config`. Methods take/return **domain models & value objects only** (cross-cutting technical ports — `IAppLoggerService`, `IClock` — handle primitives, e.g. `IClock.now(): Date`).
- DI token = interface name as a string. The field is typed by the **interface**.

## Dependency injection

- **MUST** register every provider in a module with `{ provide: 'IInterfaceName', useClass: Implementation }`.
- **MUST** type injected fields by interface, `@Inject('IInterfaceName')`.
- The module is the **only** place a concrete class name appears outside its own file.

## Error handling

- Throw **domain errors** (`extends DomainError`) for expected business outcomes.
- Technical failures (DB down, timeout) are logged and surfaced as 5xx — do not wrap them as domain errors.
- A single global `@Catch(DomainError)` filter maps `code → HTTP status`. Domain code stays HTTP-agnostic.

## Testing (create/update alongside every change — Vitest)

- **Domain** (models/VOs/services): pure unit tests, no NestJS. Cover invariants & behavior.
- **Use cases**: `Test.createTestingModule` with **mocked SPI ports** (`vi.mocked` / typed `Partial` mocks provided as `useValue`). Cover happy path, domain-error paths, edge cases; assert ports called with correct params. The use case has no `@Injectable()` — provide it as a class + its ports as `useValue` mocks.
- **Repositories**: integration-test against a real Postgres (the transaction boundary cannot be meaningfully mocked); verify row↔model mapping, atomic-claim behavior under contention, and idempotency.
- **Ownership checks**: every route that reads or writes a resource owned by someone gets a test proving another account is refused. With no RLS backstop, this suite IS the isolation proof — treat it as blocking.
- **Inbound adapters**: HTTP → `supertest` e2e-style (override guards/config, real global `ZodValidationPipe` + domain filter); assert status, response shape, 400 validation, 5xx mapping. Consumers/cron/CLI → unit-test that input is deserialized and `execute()` is called.
- Tests covering a registered business rule carry its ID in the name: `test("XXX-2 — <behaviour>", …)`.
- Shared mocks in `@test/mocks/`. AAA pattern, fresh mocks per test (`afterEach(() => vi.clearAllMocks())`), one concern per test, names `should [behavior] when [condition]`. Test behavior, not implementation.

## Definition of done — every task

1. Domain/ports defined **before** adapters.
2. Tests written/updated for each layer touched (incl. ownership/concurrency/idempotency where relevant).
3. `test` green.
4. `check:arch` green (inward-dependency rule holds).
5. `check` green (lint + typecheck).
6. Swagger updated for HTTP changes; the contracts updated if the internal contract changed.
7. No relative cross-layer imports; no concrete adapter imported outside its module; no multi-write path outside `IUnitOfWork.run`.
8. **Reviewed before commit**: `/mattpocock-skills:code-review` run from the branch base — Standards axis against this file, `ARCHITECTURE_GUIDELINES.md` and the ADRs; Spec axis against the ticket. Every Standards finding is either fixed or answered in writing, and any finding the machine could have caught becomes a proposal for a lint rule, `check:arch` or a `verify-*` script — so it is never found twice.
9. Commits in French, conventional commits (commitlint).

## Verification

```bash
pnpm --filter @{{SCOPE}}/{{PROJET}}-api test           # all tests (needs Postgres)
pnpm --filter @{{SCOPE}}/{{PROJET}}-api test:cov       # coverage
pnpm --filter @{{SCOPE}}/{{PROJET}}-api check          # lint + typecheck (tsc --noEmit)
pnpm --filter @{{SCOPE}}/{{PROJET}}-api check:arch     # domain+application compile with infrastructure excluded
pnpm --filter @{{SCOPE}}/{{PROJET}}-api check:cycles   # circular-dependency detection (dpdm)
pnpm --filter @{{SCOPE}}/{{PROJET}}-api db:types       # regenerate src/db/types.ts from the live schema
pnpm --filter @{{SCOPE}}/{{PROJET}}-api db:types:check # CI gate: fails if types.ts drifted from the schema
```

> `check:arch` must run `tsc --noEmit` against a tsconfig that includes only `src/domain` and `src/application`. If it fails, an inward-dependency rule was violated — fix the import direction, do not weaken the config.

> `check:cycles` (dpdm) complements the golden rule: it fails (`--exit-code circular:1`) as soon as an import cycle exists. Aggregate it into the root `check` and run it at `git push` (Husky `pre-push` hook).

## Generation order (follow every time)

Domain-first, working backward from the port contract:

1. `@domain` — model / value objects (invariants), output DTO, domain error(s), API port, SPI port(s). **+ tests**
2. `@application` — use case implementing the API port, injectable mapper, optional internal Zod schema. **+ tests**
3. `@infrastructure` outbound — Kysely repository implementing the SPI (+ migration if the schema changes; regenerate `src/db/types.ts`). **+ tests**
4. `@infrastructure` inbound — input DTO (`createZodDto`), controller/consumer/scheduler delegating to the API port. **+ tests**
5. Module — register repository, use case, mapper, domain service, adapter by token; add routing in `AppModule` if the module is new.

Full rationale, analogies, and expanded examples: [docs/ARCHITECTURE_GUIDELINES.md](docs/ARCHITECTURE_GUIDELINES.md).
